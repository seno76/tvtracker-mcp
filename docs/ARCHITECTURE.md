# Архитектура

Смысл разделения ровно один: **доменную логику можно проверить на выдуманных данных за
миллисекунды**, а транспорт поменять со stdio на HTTP, не тронув её ни на строку.

## Слои и правило зависимостей

Импорт разрешён только вниз. Проверяется прогоном по AST — на момент последней ревизии
нарушений нет.

```
7  server.py, cli.py        точки входа: собирают всё и запускают
6  tools/, resources.py,    слой MCP: регистрация примитивов, никакой логики
   prompts.py
5  runtime.py               как обработчики добираются до зависимостей
4  mapping.py, services.py  строки БД → доменные структуры и агрегаты
3  storage/                 SQLite: схема, репозиторий, синхронизация
2  tvmaze/, index/          источник и полнотекстовый поиск
1  domain/                  чистая логика: бэклог, вкус, вердикт, рендер
0  config, errors, log,     основание: не зависит ни от чего внутри проекта
   clock
```

| Слой | Файл | За что отвечает |
| --- | --- | --- |
| 0 | `config.py` | настройки из окружения, границы значений в валидаторах |
| 0 | `errors.py` | доменные ошибки; `httpx` наружу не выходит |
| 0 | `log.py` | stderr-логирование, контекст запроса, замер длительности |
| 0 | `clock.py` | **единственное** место, где в программу входит системное время |
| 1 | `domain/backlog.py` | что вышло и не просмотрено; все граничные случаи |
| 1 | `domain/taste.py` | профиль вкуса по истории |
| 1 | `domain/verdict.py` | рейтинги по сезонам, выбор «что включить» |
| 1 | `domain/format.py` | сборка текста ответа, усечение, человеческие сроки |
| 1 | `domain/episodes.py` | разбор и печать номеров серий (`2x03`) |
| 2 | `tvmaze/client.py` | HTTP с ограничителем частоты и backoff |
| 2 | `tvmaze/models.py` | 13 полей вместо 40; мусор отбрасывается на входе |
| 2 | `index/fts.py` | BM25 по описаниям, экранирование ввода, просмотр по фильтрам |
| 3 | `storage/` | схема с FTS5, репозиторий, синхронизация корпуса |
| 4 | `mapping.py` | строка SQLite → `ShowLine`, `EpisodeRow`, позиция |
| 4 | `services.py` | агрегаты поверх репозитория (бэклог по всем сериалам) |
| 5 | `runtime.py` | два пути к зависимостям и объяснение, почему их два |
| 6 | `tools/` | пять инструментов, по модулю на каждый |
| 6 | `resources.py` | пять ресурсов: сборка текста + тонкая регистрация |
| 6 | `prompts.py` | четыре промпта |
| 7 | `server.py`, `cli.py` | stdio-сервер и обслуживание базы вне сессии |

## Три решения, которые стоит знать заранее

**Домейн не знает ни про SQL, ни про сеть, ни про MCP, ни про часы.** «Сейчас» приходит
аргументом — только поэтому случай «серия вышла сегодня, но по UTC ещё не наступила»
вообще поддаётся проверке. Системные часы читаются в одном месте, `clock.py`.

**Логи живут на границах.** Сеть, БД и слой MCP пишут в лог; доменные функции возвращают
значения и молчат. Иначе их нельзя гонять тысячами на фикстурах без настройки.

**К зависимостям два пути, и это не небрежность.** Инструменты получают контекст
параметром — штатный механизм SDK. Статическим ресурсам SDK контекст не отдаёт вовсе,
поэтому lifespan кладёт его в держатель, а ресурсы читают оттуда. Оба пути объявлены
в `runtime.py`, чтобы менять разложение зависимостей приходилось в одном месте.

## Что где тестируется

| Маркер | Что покрывает | Сеть / БД |
| --- | --- | --- |
| `unit` | слои 0–1 на фикстурах | нет |
| `integration` | слои 2–4 и рендеры ресурсов поверх SQLite в `tmp_path`; клиент через `respx` | локально |
| `contract` | слой 6 через in-memory клиент SDK | нет |
| `regression` | закреплённые сценарии evals и сам прогонщик | нет |

Рендеры ресурсов вынесены из функции регистрации именно ради этого: `render_backlog(repo, now)`
вызывается в тесте напрямую, без поднятого сервера.

## Чего здесь сознательно нет

- **Шаблонных ресурсов** (`show://{slug}`): данные по конкретному сериалу нужны не всегда,
  а по запросу — это работа `show_profile`.
- **Мультиарендности, OAuth, удалённого транспорта.** Один пользователь, локальный запуск.
  Они утроят код и ничего не добавят к пониманию примитивов.
- **Векторного поиска.** FTS5 закрывает поиск по описанию на приемлемом уровне и не тянет
  сотню мегабайт зависимостей.
