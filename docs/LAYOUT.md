# Что где лежит и зачем

Разбор каждого файла и каталога проекта — для тех, кто такие структуры видит впервые.

## Дерево

```
tvtracker-mcp/
├── src/tvtracker/     код сервера
├── tests/             тесты
├── evals/             прогон качества: 12 сценариев с замером
├── docs/              документация
├── data/              база SQLite            ← не в репозитории
├── logs/              файловые логи          ← не в репозитории
├── .venv/             виртуальное окружение  ← не в репозитории
├── pyproject.toml     паспорт проекта: зависимости и настройки инструментов
├── uv.lock            точные версии всего, что установлено
├── .python-version    какая версия Python нужна
├── .env / .env.example  настройки: рабочая копия и образец
├── .gitignore         что не класть в репозиторий
├── README.md          описание проекта
└── LICENSE            условия использования кода
```

---

## Форматы файлов

| Расширение | Что это | Зачем |
| --- | --- | --- |
| `.py` | код на Python | сам сервер |
| `.md` | Markdown — текст с простой разметкой (`#` заголовок, `**жирный**`) | документация; GitHub показывает его как страницу |
| `.toml` | формат настроек: `ключ = значение`, секции в `[скобках]` | стандарт для настроек Python-проектов |
| `.yaml` | формат данных: вложенность задаётся отступами, без скобок | список сценариев оценки |
| `.lock` | «замок»: сгенерированный файл с точными версиями | руками не правят, только коммитят |
| `.sql` | язык запросов к базе | описание таблиц |
| `.example` | образец файла, который каждый заполняет у себя | показывает, какие настройки бывают |

**Файлы, начинающиеся с точки** (`.gitignore`, `.env`) в Linux и macOS скрыты по умолчанию.
Так помечают служебное — то, что нужно программам, а не человеку.

## Файлы в корне

### `.python-version` → `3.11`

Одна строка: какая версия Python нужна проекту. Её читают `uv` и `pyenv` и сами
подставляют нужную.

**Зачем.** У вас может стоять Python 3.9, 3.11 и 3.13 одновременно. Без этого файла
каждый запускает проект на своей версии — и «у меня работает» перестаёт что-либо значить.
Здесь нужен минимум 3.11: код использует синтаксис `str | None` и `match`.

### `pyproject.toml` — паспорт проекта

Один файл вместо пяти. В нём:

- **`[project]`** — имя, версия, зависимости (`mcp`, `httpx`, `pydantic`);
- **`[dependency-groups]`** — что нужно только разработчику (`pytest`, `ruff`, `mypy`);
- **`[project.scripts]`** — из-за этой строки работает команда `tvtracker`;
- **`[tool.*]`** — настройки инструментов: как гонять тесты, какие правила проверять.

**Зачем.** Раньше это были `setup.py`, `requirements.txt`, `pytest.ini`, `.flake8` и
`mypy.ini` по отдельности. Теперь один файл, и он стандарт языка.

### `uv.lock` — точные версии

`pyproject.toml` говорит «нужен `httpx` не ниже 0.28». Lock-файл говорит «установлен
ровно 0.28.1, вот его контрольная сумма».

**Зачем.** Без него завтрашняя установка подтянет более новую версию, и проект может
сломаться на чужой машине без единого изменения в коде. Файл генерируется автоматически
командой `uv sync`; править руками не нужно, а коммитить — обязательно.

### `.env` и `.env.example` — настройки

`.env` — пары `КЛЮЧ=значение`, которые программа читает при запуске:

```
TVTRACKER_DB_PATH=data/tvtracker.db
TVTRACKER_LOG_LEVEL=INFO
```

**Почему их два.** `.env` у каждого свой и **в репозиторий не попадает** — обычно там
пароли и ключи. Но тогда новый человек не узнает, какие настройки вообще существуют.
Поэтому рядом лежит `.env.example`: те же ключи с безопасными значениями, он коммитится.
Установка начинается с `cp .env.example .env`.

*В этом проекте секретов нет — у TVmaze нет ключа API, — но привычка правильная:
однажды секрет появится, и `.env` уже будет закрыт.*

### `.gitignore` — что не класть в репозиторий

Список того, что Git должен не замечать: сгенерированное (`.venv`, кэши), личное (`.env`),
большое (`data/` — 78 МБ базы).

**Зачем.** Репозиторий хранит **источник**, а не результат. Виртуальное окружение
воссоздаётся одной командой и весит сотни мегабайт; базу можно скачать заново. Плюс
защита от случайного коммита пароля.

### `README.md` — первое, что видит человек

GitHub показывает его на главной странице репозитория. Что проект делает, как запустить,
что умеет.

### `LICENSE` — условия использования

Простой текст без расширения. Без него по умолчанию **никто не имеет права** пользоваться
вашим кодом. Здесь MIT: «делайте что хотите, но авторство сохраните и ответственности
я не несу».

## Каталоги

### `src/tvtracker/` — код

Обратите внимание: код лежит не в корне, а внутри `src/`. Это называется **src-layout**.

**Зачем.** Без него `import tvtracker` при запуске тестов подхватит папку из проекта, а не
установленный пакет — и вы протестируете не то, что получит пользователь. `src/` делает
такую ошибку невозможной.

| Подкаталог | Что внутри |
| --- | --- |
| `domain/` | чистая логика: что накопилось, профиль вкуса, рендер ответа |
| `tvmaze/` | общение с внешним API |
| `storage/` | база данных |
| `index/` | полнотекстовый поиск |
| `tools/` | инструменты, которые вызывает модель |

Разбор слоёв и правил зависимостей — [`ARCHITECTURE.md`](ARCHITECTURE.md).

**`__init__.py`** в каждой папке — пустой файл, который говорит Python «это пакет, отсюда
можно импортировать».

**`storage/schema.sql`** — описание таблиц отдельным файлом, а не строками внутри Python.
Так его читает и подсвечивает любой редактор, а сравнивать изменения в истории проще.

### `tests/` — тесты

Разложены по типам: `unit/` (быстрые, без базы и сети), `integration/` (с настоящей
базой), `regression/` (закреплённые сценарии, которые однажды сломались).

**`conftest.py`** — особое имя: `pytest` находит его сам и берёт оттуда общие заготовки
для тестов. Импортировать не нужно.

### `evals/` — прогон качества

Не тесты. Тест отвечает «работает или нет», а прогон — «сколько это стоило»: сколько
вызовов и сколько текста ушло модели. Результат пишется в `evals/reports/`.

**`tasks.yaml`** — список из 12 сценариев в виде данных, а не кода:

```yaml
- id: 1
  ask: Сериал, где сотрудникам разделяют память
  max_calls: 1
```

### `docs/` — документация

Всё, что длиннее README. Четыре документа: дизайн, архитектура, план реализации, замеры.

**Зачем отдельная папка.** Пять `.md` в корне превращают его в свалку, и README теряется
среди них.

### `data/`, `logs/`, `.venv/` — не в репозитории

Создаются программой или установкой, в Git не попадают:

- `data/` — база SQLite, 78 МБ, скачивается командой `sync --full`;
- `logs/` — файловые логи, если включены;
- `.venv/` — виртуальное окружение: отдельная копия Python с зависимостями **только этого
  проекта**, чтобы библиотеки разных проектов не конфликтовали. Восстанавливается
  командой `uv sync`.

### Кэши: `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`, `.coverage`

Инструменты запоминают результаты, чтобы второй запуск был быстрее. Удаляются без
последствий, в Git не попадают.
